# هِمّة — خطة النموذج الصوتي المبسطة v1

التاريخ: 2026-09-21  
الفرع: `stage/speech-model-completion-20260921`

## 1. القرار

نلغي أي تصميم زائد عن حاجة المنصة. النظام الصوتي لهِمّة يتعامل مع **3 أنواع فقط** من مهام القراءة:

1. **targeted_pronunciation** — للحرف/المقطع/الكلمة عندما تكون الحركة أو الشدة أو السكون أو المد جزءًا من الهدف التعليمي.
2. **lexical** — للكلمات العامة والعبارات والجمل والنصوص عندما يكون المطلوب قراءة النص بصورة صحيحة.
3. **fluency** — للمهام الموقوتة؛ تعتمد على القراءة النصية مع الزمن.

لا يوجد مراجع بشري في مسار الطالب التشغيلي. إذا لم تكن الأدلة كافية فالنتيجة هي `retry_required` ويُطلب إعادة التسجيل.

## 2. قاعدة المحتوى الجديدة

**نوع التحليل لا يُستنتج من كمية التشكيل في النص.**

الجمل والنصوص قد تكون قليلة التشكيل أو بلا تشكيل تقريبًا. لذلك:

- `display_text`: النص الذي يراه الطالب، بأي درجة تشكيل يعتمدها المحتوى.
- `lexical_reference`: نفس النص بعد التطبيع وإزالة التشكيل للمقارنة النصية.
- `speech_mode`: يأتي من Profile المهمة التعليمية.
- `pronunciation_focus`: يوجد فقط عندما تكون الحركة/الشدة/السكون/المد جزءًا من المطلوب.

بهذا يمكن تحديث النصوص دون إعادة تصميم النموذج.

> ملاحظة حالية: snapshot الموجود في `catalog.json` داخل هذا الفرع لا يزال يحتوي تشكيلًا كثيفًا في بعض الجمل والفقرات. هذه الخطة لا تعتمد عليه، ومقصودها العمل مع المحتوى الجديد حتى بعد تخفيف التشكيل.

## 3. المسار الأول — الجمل والنصوص والقراءة العامة

يُستخدم `lexical`.

```
audio
  -> quality check
  -> Arabic ASR
  -> normalize Arabic + remove diacritics
  -> reference-guided word alignment
  -> Correct / Deletion / Insertion / Substitution
  -> lexical accuracy
```

لا نحاول الحكم على كل فتحة وكسرة داخل جملة أو فقرة.

القرار النصي البسيط:
- تطابق كامل بعد التطبيع والمحاذاة → `correct`.
- أول حذف/إضافة/استبدال → `retry_required` وإعادة تسجيل واحدة حتى لا نظلم الطفل بسبب خطأ ASR.
- إذا تكرر نفس الخطأ بعد إعادة التسجيل → يمكن تثبيته `incorrect`.
- تسجيل غير واضح أو مزود بلا دليل كافٍ → `retry_required`.

## 4. المسار الثاني — الحروف والمقاطع والكلمات الحساسة

يُستخدم `targeted_pronunciation`.

أمثلة:
- `مَ` — حركة قصيرة.
- `بِ` — حركة قصيرة.
- `شَمْس` — السكون جزء من الهدف.
- `قِطَّة` — الشدة جزء من الهدف.

هنا لا يكون نص ASR وحده حكمًا نهائيًا.

نستخدم:
1. نتيجة ASR كدليل.
2. Pronunciation Assessment كدليل ثانٍ.
3. قائمة aliases/confusions صغيرة للهدف القصير حتى لا نعاقب الطفل بسبب تهجئة المزود.

مثال:

```
target: مَ
possible ASR spellings: م / ما / ماء / ma
```

هذه aliases لا تعني أن `ماء` نطق صحيح؛ معناها فقط **لا تحكم خطأ من transcript وحده**. القرار النهائي يحتاج دليل النطق أيضًا.

إذا الأدلة متعارضة أو ضعيفة: `retry_required`.

## 5. المسار الثالث — الطلاقة

يُستخدم `fluency`.

هو نفس المسار النصي مع إضافة الزمن:
- عدد الكلمات المقروءة.
- الكلمات الصحيحة.
- C/D/I/S.
- الزمن.
- معدل القراءة الذي تحدده سياسة النشاط.

لا ندخل تحليل الحركات المفردة في فقرة موقوتة.

## 6. Provider Confusions / Aliases

نحتاج Configuration صغيرًا، وليس قاعدة معرفة ضخمة.

```json
{
  "target": "مَ",
  "asr_aliases": ["م", "ما", "ماء", "ma"],
  "effect": "do_not_fail_from_asr_only"
}
```

القواعد:
- alias يمنع false negative من الـASR.
- alias لا يمنح `correct` بمفرده في `targeted_pronunciation`.
- القوائم تُضاف فقط بعد ظهور خطأ مزود معروف في التجربة.
- لا ننشئ قاموسًا ضخمًا مسبقًا.

## 9. قرار التشغيل

الـProduction المستقبلي لا يحتوي مراجعًا بشريًا في المسار الطبيعي.

```
correct
incorrect
retry_required
```

وعند `retry_required` يُعاد التسجيل تلقائيًا ولا تُحسب محاولة خاطئة أكاديميًا.

## 10. ترتيب التنفيذ داخل هذا الفرع

### P1 — Profile
اعتماد `speech_task_profiles_v1.json` كمصدر تصنيف مهام التسجيل.

### P2 — Lexical path
ربط `lexical` و`fluency` بالـASR + alignment الموجودين.

### P3 — Targeted pronunciation
تشغيل Pronunciation Assessment فقط لمهام `targeted_pronunciation`.

### P4 — Alias rules
إضافة ملف صغير لأخطاء ASR المعروفة عند ظهورها أثناء الاختبار.

### P5 — Decision
بناء قرار موحد:
`correct | incorrect | retry_required`

### P6 — Speech Lab
استخدام Speech Lab لاختبار عينات قصيرة وجمل ومقارنة Azure/Google، وليس كمنصة مراجعة بشرية تشغيلية.

### P7 — Tests
تغطية السيناريوهات:
- `مَ` وASR يعيد `ما/ماء`: لا يُرفض من ASR وحده.
- `مَ` ونطق صوتي غير واضح: retry.
- حرف/حركة خاطئة بوضوح: incorrect.
- جملة صحيحة مع اختلاف التشكيل: correct.
- حذف كلمة من جملة: deletion ثم retry في المحاولة الأولى.
- تكرار نفس الحذف بعد إعادة التسجيل: incorrect.
- إضافة كلمة: insertion ثم retry في المحاولة الأولى.
- تسجيل صامت/ضعيف: retry.
- فقرة موقوتة: lexical + time.

## 11. شرط الدمج مستقبلًا

لا دمج الآن.

يصبح الفرع مرشحًا للدمج فقط بعد:
1. اختبار المسارات الثلاثة.
2. تجربة مزود حقيقي على الحروف والجمل.
3. توثيق aliases التي ظهرت فعلًا فقط.
4. إثبات أن `retry_required` يمنع الأحكام غير الموثوقة.
5. بقاء `academic_effect = none` أثناء مرحلة المختبر حتى اعتماد النسخة النهائية.
