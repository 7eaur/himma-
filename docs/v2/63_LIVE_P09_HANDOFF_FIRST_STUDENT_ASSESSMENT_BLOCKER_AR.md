## ب. تفسير دقيق لفجوة «تعذر فتح الاختبار» عند أول دخول

**مسار البدء الحقيقي الحالي:**

- `apps/web/src/app/student/login/page.tsx`: قبول رمز الطفل عبر `POST /api/auth/student-login` ثم `router.replace("/student")`.
- `apps/web/src/app/student/page.tsx`: يجلب `GET /api/v2/student/home` أولًا؛ لا يعرض `V2StudentDashboard` إلا عندما يكون `payload.mode === "v2"`. خلاف ذلك ينتقل إلى `GET /api/profile` وواجهات V1.
- `services/api/v2_student_readmodel.py`: `mode = "v2" if journey or active_assessment or active_lesson else "legacy"`. لذلك **الطفل الجديد تمامًا من دون رحلة/جلسة V2 يُصنَّف legacy**، مع أنه يُراد منتج V2 فقط. هذه **فجوة بنيوية مثبتة من الكود** وتحتاج قاعدة تسجيل/ترحيل صريحة، لا حذف البيانات القديمة.
- إذا عرضت لوحة V2 فالزر في `apps/web/src/app/student/V2StudentDashboard.tsx` يرسل `POST /api/v2/assessments/pretest/start`. تظهر الرسالة «تعذر فتح الاختبار» عند فشل HTTP دون `detail` نصية (أو فشل JSON)، وهناك حالات أخرى قد تظهر تفاصيل FastAPI أو خطأ JavaScript مختلفًا.
- `services/api/v2_assessment_runtime.py` في `start_assessment` يتحقق من جلسة `AssessmentSession` فعالة **سواء V1 أو V2**؛ ويرفض جلسة سابقة نوعها مختلف أو من V1 بـ409، ويتحقق من `AssessmentRetakeAuthorization` للقبلي الذي سبق إكماله، ومن حالة `StudentJourney` واختلاف `content_release_id`؛ ثم يستدعي `register_candidate_release`. كما يمكن لـ`_require_preview_student` أن يمنع الوصول بحسب Runtime flags. **لا تتجاوز هذه الحمايات** لتصحيح رسالة الواجهة، بل أصلح خطة الانتقال واستعادة الجلسات مع الحفاظ على التقييم القديم.
- `apps/web/src/app/api/[...path]/route.ts` يمرر الطلب للخلفية عبر `NEXT_PUBLIC_API_URL` مع cookie وCSRF؛ افحص صلاحية الوجهة/الكوكي و`x-request-id` وحالات 401/403/409/422/503/500/timeout دون نشر الكوكي أو الرمز.
- `apps/web/src/app/student/assessment-v2/[sessionId]/page.tsx`: بعد نجاح البدء، يستعيد `GET /api/v2/assessments/sessions/{id}`. يجب أن تغطي الاختبارات أيضًا تحميل أول سؤال `V2-PRE-Q01` والانتقال والوسائط، لا مجرد نجاح POST.

**فرضيات مرتبة لاختبار السبب الحقيقي:** (1) طفل جديد يدخل V1 بدل V2 بسبب `mode=legacy`؛ (2) بداية تقييم V2 ترفضها جلسة V1 متعارضة أو محاولة سابقة غير مخوّلة؛ (3) Runtime flag أو اختلاف release pinned؛ (4) Proxy/env/كوكي/CSRF أو تحديث الواجهة والخلفية على نسختين غير متوافقتين؛ (5) تعذر إنشاء الجلسة بسبب قيد DB/ترحيل. اعمل إحصاء لأكواد الأخطاء في بيئة الاختبار وسبب 409 الحقيقي، **ولا تشخّص اعتمادًا على النص العام فقط**.
