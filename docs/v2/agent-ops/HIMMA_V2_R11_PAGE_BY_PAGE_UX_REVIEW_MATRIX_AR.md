**قرار المالك 2026-11-01:** أثناء مراجعة كل صفحة لا يكتفي الفاحص بالتأكد أنها تعمل؛ بل يسأل من منظور مسؤول المنتج ومختص UI/UX: **هل يجب أن تكون هذه الصفحة موجودة بهذا الشكل؟ هل خطوتها التالية بديهية؟ لو أعدنا تصميمها اليوم دون ارتباط بتاريخ التطوير، هل سنختار التنظيم نفسه أم هيكلًا أبسط وأوضح؟**

**الحالة:** جرد أولي من الشيفرة فقط، **لم يُنجز بعد فحص بصري وتشغيلي مستقل لكل صفحة** ولا تُعتبر R11 مغلقة. أُعدّت هذه المصفوفة لتقود التنفيذ دفعة بدفعة دون قرارات شكلية متعجلة.

## 1) قاعدة المراجعة النقدية الإلزامية

لكل صفحة وبالترتيب:
1. **هدف المستخدم:** من هو المشرف الذي يستخدمها، ما السؤال الذي جاء ليجيب عنه، وما القرار/الفعل الأساسي الذي يجب إنجازه خلال أقل خطوات معقولة؟
2. **إعادة تقييم التخطيط من الصفر:** هل العنوان والمعلومات والأزرار والأولوية والتبويبات والتسلسل منطقية؟ هل الصفحة ضرورية مستقلّة؟ هل الدمج أو إعادة التقسيم أو الاكتفاء بمودال/تبويب أوضح؟ لا تلتزم بالتخطيط القديم لمجرد أنه موجود.
3. **تدقيق المحتوى الظاهر:** وصف مفيد بدل المصطلحات والمفاتيح والتفاصيل الداخلية؛ احذف التعليمات التطويرية، الأزرار غير الفعالة، البطاقة/التكرار عديم القيمة، والتأكيدات غير اللازمة بعد اختبار الأثر. لا تكشف إجابات خاصة أو بيانات صوت الأطفال.
4. **مراجعة كل حالة استخدام:** بيانات كاملة، فارغة، تحميل، خطأ 4xx/5xx، شبكة بطيئة/منقطعة، إقرار نجاح مؤكد، ضغط متكرر، صلاحية غير كافية، نوافذ فرعية وتحديث البيانات بعد العملية. لا يكفي مسار Happy Path.
5. **اتساق التصميم والأدوات:** الهوية وRTL واللون والخط والمسافة وكثافة البيانات وحجم الأزرار واللغة، ومواءمة `AdminUI` مع نماذج الصفحات والجداول والتبويبات والإشعارات العامة بدل تراكم حلول متوازية.
6. **القرار الهندسي والتجربة:** لكل مشكلة سجل «المشكلة ← سببها ← البدائل ← الحل الأنسب ولماذا ← ملفات التغيير ← الاختبار/اللقطة ← حالة النشر»، واختبر الهاتف 320/375/390px والكمبيوتر 768/1024/1440px بلوحة المفاتيح واللمس والقراءة العربية.
7. **ضابط التعديل:** يحق تغيير تخطيط الصفحة جذريًا إذا أثبتت المراجعة أنه أصلح للمشرف، لكن مع المحافظة على وظائف V2 والإجراءات المعتمدة وأدلة الطلبة، وعدم إدخال V1 أو فتح ميزة تجريبية. لا يُزال مسار أو مكون حتى تُفحص جميع استدعاءاته واختباراته.

**قرار الإغلاق لكل صفحة (يسجل واحدًا مع الدليل):** إبقاء محسّن / إعادة تصميم وتوزيع / دمج أو توجيه آمن / إزالة عنصر زائد / إضافة مكون ناقص. الحالات: لم تُفحص، قيد الفحص، عيب مكتشف، قيد الإصلاح، تحقق ناجح، مغلقة ومنشورة.

## 4) الدفعة الأولى — نتائج فحص وإصلاحات مصدرية (2026-11-01)

**نطاق الدفعة:** تسجيل الدخول والرئيسية وقائمة الطلاب وإنشاء طالب. **المراجعة النقدية شملت الكود وتخطيط التدفق، وتتوفر لقطة هاتف 390px وكمبيوتر 1440px لشاشة الدخول فقط.** لا يُعلن إغلاق الصفحات المحمية قبل التقاطها ومراجعتها على الهاتف والديسكتوب ببيانات اصطناعية.

- **تسجيل الدخول:** التخطيط المقسوم على الكمبيوتر وبطاقة واحدة على الجوال واضحان في لقطات Playwright الحقيقية؛ لا حاجة لإعادة رسم الصفحة من الصفر. عيب مثبت في تباين نص المساعدة السفلي نتيجة `opacity:.7` أصلح في `apps/web/src/app/globals.css`، وأُعيد فحص التجاوب بصريًا. أضيف قفل فوري لطلبات دخول المشرف المتكررة والرد العربي الآمن إذا أرجع الخادم `detail` غير نصي، مع اختبارات. قرارات: **إبقاء التخطيط وتحسين التفاصيل**.
- **الرئيسية:** كانت بطاقات «تحتاج متابعتك» قابلة للنقر رغم وجود صفر مهام، وكانت روابط قراءات الاختبارات والدروس تتجاوز المركز الموحد إلى صفحات فرعية. أصبح العرض يبرز المهام ذات العدد الموجب فقط ويوجّه إلى تبويب المركز الصحيح، مع رسالة فارغة مفهومة؛ استُبدلت أخطاء «V2» التقنية الظاهرة للمشرف بنصوص مناسبة. قرار: **إبقاء الصفحة مع تحسين تسلسل إجراءاتها**، مع فحص بصري محمي لاحق.
- **قائمة الطلاب:** كان عرض عدم وجود نتائج البحث يقترح إضافة طالب ولو كانت المشكلة مجرد تصفية، ما يزيد احتمال الحسابات المكررة. أصبح يقترح **مسح البحث والتصفية** عند استخدامهما، ويقترح الإضافة فقط إذا لم يكن هناك طلب بحث/تصفية؛ حذف تعبير «العينة» غير الملائم للإنتاج، وحُفظ debounce البحث. قرار: **إبقاء قائمة الطلاب وتحسين الحالات الفارغة**؛ فحص الهاتف/الجدول ما زال مطلوبًا.
- **إضافة الطالب:** أُزيل حقل الصف الثابت الذي بدا كحقل إدخال بدون وظيفة (بقيت معلومة الصف الثالث في الوصف)، واختصر نص إنشاء الرمز، وأضيف منع إرسالين متزامنين، ودعم أرقام `٠-٩` و`۰-۹` للرمز اليدوي مع تحويلها لصيغة API دون تخمين، ورسالة واضحة إذا فشل النسخ بدل نجاح كاذب، وتحذير عند استجابة إنشاء غير موثوقة قبل الضغط مرة أخرى لمنع تكرار الحساب، ورابط مباشر للملف الجديد من معرّف الحساب المعتمد. قرار: **تبسيط النموذج وإكمال الإجراء التالي**.
- **ملف الطالب — جرد أولي فقط:** ظهرت في الكود معرفات درس/طالب داخل العرض وأسباب `reason_code` الخام، وحقل رمز يدوي يزيل الأرقام العربية، وتكرار بعض أنماط المكونات والإشعارات. لا تُحذف معلومات يحتاجها المشرف بلا تحقق؛ تدخل ضمن المجموعة التالية مع إصلاح المصدر واختبارات ولقطات وحراسة خصوصية.
- **الاختبارات:** على SHA كود `01dce0d995fe4c51119bd9e5eb9781d2c190d8e5` اجتازت Frontend `264/264` وSecurity وM04، مع معاينة لقطة الدخول المصححة. **Backend وM09 كانتا قيد التنفيذ عند هذه القراءة**، فلا تُعلن خضرتهما أو النشر من هذا الملف. التزام توثيق لاحق لا يغير كود هذه الدفعة.
