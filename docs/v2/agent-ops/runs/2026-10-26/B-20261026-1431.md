## Root cause and correction
Previous boundary validation checked session_id/kind and top-level answered, but accepted an `interaction` for a different assessment role or question index, e.g. `session.progress.answered=1` paired with `interaction.progress.index=1` rather than the authoritative next question 2. This could display the wrong question even when session identity matched. The backend serializer uses `session.v2_question_index+1`, `stage=session_type` and `question.role=session_type`, so the additional invariants match the live API contract.

The GET browser regression alters only a pretest question role in a successful upstream response; it must hide the question and recover via retry. The POST regression commits an answer upstream, alters only the browser-facing next-question index, verifies fail-closed and GET-only recovery with one answer after reload.
