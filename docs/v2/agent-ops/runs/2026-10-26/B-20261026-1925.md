## Root cause and correction
The UI's GET/POST `isAssessmentPayload` guard accepted `state=completed` or review states with `progress.answered=0` whenever `interaction=null`. Such a malformed or stale 200 could display a false completion/review screen even though the backend had not received all thirty answers. The server's `_finish_if_ready` explicitly requires `answered==30` before entering terminal states. The UI now mirrors this invariant. New Playwright regression starts a genuine synthetic student's pretest, modifies only the browser-facing first GET to a false terminal state, asserts no completion screen, then retries a genuine GET and expects question 1. This does not invent student grades or mutate the backend.
