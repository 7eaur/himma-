## Root cause
`play()` awaited an asynchronous browser promise then unconditionally changed player state to `ready` or `blocked`. A media error or a server completion-save transition arriving before the promise settled could be overwritten by the old promise. Native `canplay` and metadata events could also dismiss the explicit autoplay-blocked prompt without the learner pressing play. The fix gates asynchronous results to playback states only, preserves blocked state during native readiness events, and sets ready explicitly on replay. No progress/answer logic changed.
