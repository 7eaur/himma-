## Root cause and correction
Previously `VideoPlayer` retained component-local `state`, `completing` and `lastCheckpoint` when the `src` prop changed without unmounting. A delayed completion acknowledgment or rejected `play()` from the prior lesson could therefore update the next lesson's UI, and its last checkpoint could suppress the new video's first checkpoint. The final implementation renders a `VideoPlayerInstance` with `key={props.src}`, so each source has isolated lifecycle and refs. It keeps the existing save-confirmation and retry behavior intact. The tests simulate an unresolved previous completion, a delayed previous playback rejection, and source-specific checkpoint tracking.
