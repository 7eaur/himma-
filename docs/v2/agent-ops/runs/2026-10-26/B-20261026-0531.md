## Root cause and change
The student detail page used `Promise.all` to request primary identity plus three optional historical V1 data sources. A single **network rejection** (not HTTP 503 response) from journey/rewards/adaptation rejected the whole promise, clearing `student` and showing a misleading full-profile error despite a valid primary identity and V2 source. The patch fetches primary identity separately, validates the returned ID, and fetches each secondary source independently with explicit error state and retry. A keyed `StudentDetailView` remains the isolation boundary on route changes.

The cross-profile test now holds the second GET while switching A→B, then holds the first GET while switching B→A, asserting no prior identity or revealed access code is rendered during either wait. The network failure test aborts a journey request and verifies the real student and V2 panel stay visible while the legacy tab shows an error, then recovers through retry.
