## Root cause and fix
Two rapid playback requests can coexist while the blocked overlay remains visible. The older request can reject *after* the newer one succeeds, incorrectly restoring `blocked` and hiding native controls. Similarly, a promise from before a media error can reject after explicit reload and mark the new load as blocked. A monotonic `playAttempt` ref makes only the newest play result authoritative; media error and explicit retry invalidate pending results. This is a targeted state-machine guard, not a relaxation of tests or media completion policy.
