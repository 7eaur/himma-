## Root cause / scoped fix
- The assessment page previously retained its React state while Next could reuse the dynamic-route page for a different `sessionId`. An in-flight GET could return data belonging to a different session, and the component did not compare `data.session.session_id` with the requested route. This is a **defensive isolation gap established by source inspection**, not evidence of an observed live cross-student disclosure.
- `AssessmentV2Page` now mounts an inner `AssessmentV2Session` keyed by the route parameter, isolating session state across client navigation.
- A successful HTTP 200 is no longer sufficient: if the payload lacks a session, has a different `session_id`, or invalid `kind`, the UI fails closed and offers retry; it does not render a question/progress for another session.
- Added a Playwright test to the **existing** CI/M09-included `v2-pretest-recovery-matrix.spec.ts`. A synthetic student starts a real pretest; one real upstream GET is modified **only in the browser response** to return a different session ID. The test expects no `v2-interaction-player`, an error/retry UI, then successful retry on the original session with `answered=0`. No backend/learning rules changed.
