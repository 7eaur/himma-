## Root cause, correction, and limits
The previous `startRecording()` awaited `getUserMedia()` without invalidating a pending permission request when the question unmounted. A late grant could start an orphaned recorder and leave the child's microphone active. Also, `onstop` created a Blob even if no audio chunks arrived, permitting a zero-byte recording to be submitted as if valid.

The patch introduces a mount-bound request generation and a synchronous pending-request guard; a stale permission result immediately stops its stream and cannot create a recorder. Unmount detaches recorder callbacks, stops recording and media tracks. Capture construction/start failures release tracks. A zero-byte Blob is rejected with an Arabic retry message and the submit button stays disabled. The recording button indicates pending microphone permission. Existing upload idempotency behavior remains unchanged.
