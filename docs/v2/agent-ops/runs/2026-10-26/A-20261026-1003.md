## Root cause and fix
`media[media_id].state === "ready"` is a server-side availability declaration, not proof that the child's browser decoded the image or could play audio. Before this patch the ready flag allowed submission after browser load/play errors. `InteractionPlayer` now records failed media IDs on `Image.onError`, `Audio.onerror`, and rejected `Audio.play()`; a failed referenced medium disables selection/submission and shows the existing fail-closed alert. Audio playback success clears its failure state to permit a retry without discarding the answer. The selected-image tray also reports load errors. Image failure tells the learner to refresh, preserving the backend's saved checkpoint.

## Tests and limitations
- Jest test 1 creates a nominally ready image whose browser load fails; selection and submit become disabled.
- Jest test 2 simulates a rejected audio play followed by a successful retry; submit is disabled after failure and enabled after success.
- The tests were **not run locally**. GitHub gates were still running at last check. This is **not** visual/device validation and does not certify the actual lesson media bank.
