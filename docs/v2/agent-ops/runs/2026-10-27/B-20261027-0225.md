## Why this change

The existing `logoutState === "pending"` guard depends on React state committing between user actions. Two taps dispatched in the same React batch can both enter `logout()` before the new state is visible. Concurrent POSTs may return in different orders and cause a misleading failed-logout screen after another request succeeded. `logoutRequestRef` now closes the request gate synchronously, and a rejected attempt reopens it only for explicit retry. This does not alter backend authorization or session semantics.
