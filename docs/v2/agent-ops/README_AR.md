## دورة العامل A/B الملزمة
1. افحص `CONTROL.json.mode`: `PAUSED` يعني **توقف عن التعديل** وسجّل حالة؛ `ACTIVE` يعني البدء. امتثل لتعليمات المشرف المصنفة `BLOCKER` قبل أي عمل.
2. افحص `CONTROL.json.lease` وHEAD الحقيقي. عند Lease عامل آخر نشط، لا تكتب في الملفات المتداخلة؛ أنجز تحليلًا/اختبارًا للقراءة فقط أو وثّق التعارض. لا تتجاوز lease منتهيًا آليًا دون التأكد من حالة صاحب التشغيل والتغييرات التي رفعها.
3. خذ Lease بتحديث ملف `CONTROL.json` **ذريًا** عبر GitHub blob SHA/CAS وHEAD متوقع، لمدة لا تتجاوز 27 دقيقة؛ دوّن `run_id` و`base_head` و`scope`. إن فشل تحديث CAS أعد القراءة كاملة ولا تستخدم force-push.
4. اختر مهمة `READY` بالأولوية التي يعتمدها المشرف؛ احصر الملفات المقصودة ولا تنفذ تغييرًا تربويًا/حذفًا/دمجًا دون إذن المالك. افحص السبب الأصلي، نفذ تحسينًا صغيرًا مترابطًا، ثم اختبارات مستهدفة؛ CI شامل بعد **دفعة** لا بعد كل سطر.
5. قبل كل Commit جديد أعد قراءة HEAD، قارِن الملفات التي تغيّرت أثناء جلستك، ثم استخدم تحديث GitHub fast-forward مع `expected_sha`. عند وجود commits من مهام أخرى أعد بناء التغيير على HEAD الحالي **ولا تستبدل** عملًا أحدث.
6. حرر Lease في commit تسليم موحّد، ثم حدّث `LATEST_HANDOFF.md` و`RUN_LOG.md` وملف فريد في `runs/YYYY-MM-DD/ROLE-YYYYMMDD-HHMM.md`. لا تقل «نجحت CI» إذا كانت جارية أو على SHA آخر.
7. لو لم تستطع حفظ التسليم في GitHub، اعتبر الجلسة `BLOCKED` وارسل تقريرًا صريحًا في نتيجة المهمة المجدولة مع آخر SHA معروف ولا تزعم استلامًا ناجحًا.

## المشرف C — صاحب مراجعة القبول الفني
- يتحقق بنفسه من commits العاملين، أثر الملفات، مصدر البيانات، privacy/authorization، GitHub Actions وRailway، ولقطات Playwright الفعلية؛ لا يكتفي بملاحظات العمال.
- يسجل لكل Run حالة `ACCEPTED`, `REWORK`, `BLOCKED`, `PENDING_GATES` مع SHA الدليل وملاحظات إعادة الإنتاج داخل `SUPERVISOR_DIRECTIVES.md`، ويحدّث أولويات `TASK_QUEUE.md`.
- له إصلاح خلل محدد مباشرة إذا لم يكن هناك Lease عامل يتعارض مع الملفات؛ **يمنع** force-push ودمج main وحذف V1 وترقية حالة اعتماد بلا نتائج.
- عند خطأ أمني/تلف محتمل يضبط `CONTROL.json.mode=PAUSED` و`stop_reason` ويوجه العاملين؛ الاستئناف بعد تحقق خطر واضح.
- إذا لم ينتهِ B قبل `:50` يسجل `PENDING_GATES` ولا يراجع عملاً غير منشور. عند الساعة القادمة يراجع الـSHA الجديد.
- القرار النهائي **اعتماد المرحلة أو تغيير التعليم/الصوت/النشر والدمج** للمالك؛ رأي المشرف الفني لا يحل محله.

- عدم المساس بـ`main` أو `stage/02-content`؛ V1 تاريخي للقراءة/التوافق، لا حذف أو إظهار تقدمه كأنه V2.
- لا تغيّر أسماء الدوال أو تضع ترقيعات تختبئ وراء إسكات اختبارات؛ توثيق الإصلاح والاختبار الذي يكشف عودة الخطأ واجب.

- الفشل في التحقق أو نقص الصلاحيات = تعثر مذكور، وليس قبولًا صامتًا.
