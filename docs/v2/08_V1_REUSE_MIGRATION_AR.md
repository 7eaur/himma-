# هِمّة V2 — إعادة استخدام V1 والترحيل

**الحالة:** معتمد كنهج

## الأصل

فرع الإنتاج الحالي وعقوده الحية هي مرجع التنفيذ الحالي. V2 تبنى فوقه تدريجيًا.

## ما نحتفظ به قدر الإمكان

- الحسابات والطلاب وأكواد الدخول.
- L1/L2/L3.
- Pretest/Posttest.
- Attempts.
- Content Items / Steps / Options بعد توسيعها.
- Media Assets.
- التسجيل الصوتي ومراجعة المشرف.
- Content Releases.
- Draft / Approved / Publish.
- Adaptation Decisions.
- Reinforcement Cycles.
- Admin Content Preview.
- Runtime/API الحالية حيث يمكن.

## ما يتغير

1. تحويل Core Activity إلى Lesson حقيقي.
2. إضافة أنواع Step مثل:
   - intro
   - explanation
   - worked_example
   - guided_practice
   - summary
   - independent_check
3. السماح بأكثر من نوع تفاعل داخل الدرس.
4. ربط الدرس بـSkill Group وإبقاء Evidence Type عند الحاجة.
5. إعادة Mapping المحتوى القديم إلى الـ19 Core الجديدة.
6. إعادة Mapping الـ30 Pre والـ30 Post.
7. تعديل التكيف ليتعامل مع Independent Check وSupport بدل الاعتماد على Activity Score فقط.

## ما لا نفعله الآن

- لا إعادة بناء شاملة لقاعدة البيانات قبل إثبات الحاجة.
- لا CMS كامل كشرط أول.
- لا استبدال كل المحتوى القديم تلقائيًا.
- لا حذف Runtime V1 قبل اكتمال Migration واختبارات القبول.

## استخدام المحتوى القديم

كل عنصر قديم يصنف:
- reuse as-is
- reuse with edit
- move to guided practice
- move to independent check
- move to support
- retire

القرار تربوي أولًا ثم تقني.
