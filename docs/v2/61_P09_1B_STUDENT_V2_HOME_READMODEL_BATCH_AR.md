# هِمّة V2 — دفعة P09.1-B: عقد بيانات موحّد قابل للقراءة

**التاريخ:** 2026-10-25  
**الفرع:** `v2/01-learning-foundation-20261007`  
**المرجع السابق:** `60_P09_1A_CURRENT_ACTION_AND_CATALOG_SOURCE_FIX_AR.md`، `58_P09_0_SOURCE_OF_TRUTH_CONTRACT_FOR_P09_1_AR.md`  
**النطاق:** مصدر الطالب والمشرف للقراءة فقط، تجربة V2 داخل لوحة الطالب القديمة، واختبارات حالات الحفظ والحقوق. هذه دفعة واحدة متكاملة؛ لا دمج `main` ولا اعتماد إنتاج.

## 1. السبب والحل

كانت بطاقة V2 داخل صفحة `/student` تستدعي `current-action` وحده، ولا تملك مصدرًا رسميًا لعدد دروس الطالب، وكانت معلومات V1 تُستخدم في نفس الصفحة. أُضيف `services/api/v2_student_readmodel.py` كإسقاط واحد من جداول V2 الحقيقية دون إنشاء قاعدة جديدة أو إعادة تسمية الدوال. عقود القراءة:
- `GET /v2/student/home` — الطالب صاحب الجلسة فقط، مع تمييز `mode = legacy|v2`.
- `GET /v2/student/admin/students/{student_id}/home` — المشرف فقط؛ نفس الإسقاط ليس رخصة لكشف رمز الدخول أو ملفات الطفل.
- `current_action` يُعاد استعماله من المحرك الحالي بدل إعادة شجرة قرارات موازية داخل React.
- `journey` تتضمن `StudentJourney.current_level/current_lesson_id/placement_state/status` وإصدار البنك المثبت، وليس مستوى V1 متى وجدت رحلة V2.
- `progress` يفصل `completed_lessons` عن `skipped_by_placement` ويحدد `assigned_lessons`. يعد `LessonSession.status=completed` **مرة واحدة لكل lesson_id** ضمن `content_release_id` المعيّن فقط؛ حالة `waiting_review` لا تعد مكتملة.
- `display_percent=null` أثناء القبلي أو عند فقدان صلاحية إسقاط إصدار المحتوى، بدل 0% كأنها نتيجة منجزة. عند التسكين المكتمل تساوي النسبة `completed/assigned`.
- `assessments.pretest|posttest`: حالة/معرف الجلسة فقط للتقييم الجاري، ولا تُعرض الدرجة إلا عندما يكون التقييم مكتملًا و`official_for_reporting=true`. درجة `99` غير رسمية لا تعرض.
- `rewards: {state: "not_implemented_v2"}` لمنع استعارة نجوم V1 أو منح مكافآت مزيفة.
- `data_status=partial` عند اختلاف snapshot البنك المثبت مع checksum الموجود، دون إسقاط التقدم على بنك مختلف أو إرسال `private_answer`.
- `test_only=true` صريح حتى اعتماد الوسائط والمنتج.

## 2. الربط في الواجهة

تقرأ بطاقة `v2-learning-preview` البيانات من `/api/v2/student/home` بدل endpoint قرار جزئي، وتستخدم `current_action` القادم من المصدر الموحد نفسه. إذا كان الطالب في رحلة V2، تعرض عدد دروسه المكتملة والمخصصة ونسبته إن كانت قابلة للحساب، أو حالة انتظار التسكين/نقص البيانات، مع ذكر انتظار مراجعة المشرف. تظل عبارة `TEST ONLY` واضحة.

**حد هذه الدفعة المقصود:** بقية هيكل `/student` ما زال فيه أقسام V1 لم يُحوّل بعد؛ لا ندعي انتهاء `P09.1-C` أو إزالة التداخل البصري نهائيًا. إزالة الأجزاء القديمة للرحلات المصادق عليها ومراجعة انسياب واجهة الهاتف هدف الدفعة التالية بعد نتائج هذه البوابة.

## 3. التحقق الأمني والوظيفي

`services/api/test_v2_student_readmodel.py` يفحص:
1. طالب V1 من دون رحلة V2: GET لا ينشئ أي رحلة، لا يحسب نسبة، ولا يمنح نجومًا.
2. قبلي V2 بدأ ولم يُعتمد: `current_action=assessment` والنتيجة/nسبة التقدم `null`.
3. رحلة موثقة L2 مقابل `Student.current_level=L1`: عدد المكتمل والمستثنى يتوازن على 19 درسًا ومصدر المستوى الصحيح.
4. جلستان مكتملتان لنفس الدرس: يحسب درسًا واحدًا، ولا يحسب `waiting_review`.
5. دور مشرف فقط في `admin/students/.../home`؛ رفض الطالب برمز 403 وإخفاء `access_code/private_answer`.
6. درجة تقييم مكتمل غير رسمي: لا تسرب النتيجة.
7. تغير checksum بين البنك المثبت والسجل: `partial` بلا رقم تقدم وهمي.

هذه السيناريوهات تُشغّل ضمن اختبارات الخلفية الموجودة، ولا يُنتج كل تعديل صغير تشغيلًا مستقلًا من طرفنا.

## 4. بوابة قبول الدفعة

لا يُعتمد `P09.1-B = PASS` إلا إذا نجح فحص backend وfrontend/security وE2E وM09 على **Commit الدفعة نفسه**. يجب أيضًا اختبار صور بطاقة V2 الفعلية في الدفعة التالية قبل اعتماد توحيد تصميم كامل.

**ملاحظة تنفيذية:** نستخدم GitHub Actions بعد **تجميع عدة ملفات مترابطة في Commit واحد**، بدل رفع تعديل واحد لكل اختبار أو نص. ينطبق الأسلوب نفسه على بقية P09؛ تحفظ الفحوص السريعة داخل التطوير وتُراجع بوابات CI الشاملة دفعةً واحدة.
