**النطاق:** تحليل وتوثيق فقط؛ لم يُعدّل كود التطبيق أو البيانات أو النشر.

## الخلاصة التنفيذية

مسار المحتوى وقت التشغيل موحّد: مصادر مؤلفة متعددة ← المجمّع القانوني ← ناشر معاملات ← PostgreSQL ← API ← الواجهة. الواجهة لا تنشئ الأسئلة أو الدرجات أكاديميًا، بل تعرض ما يصلها من API. البناء النهائي الذي فُحص يحتوي 125 عنصرًا و44 مهارة، دون تكرار في المعرّفات القانونية أو المفاتيح الثابتة.

لكن توجد تعارضات حقيقية، أهمها في المستوى الثالث: خريطة التقوية تربط بعض المهارات بعناصر لا تطابقها دلاليًا، ويوجد نشاطان متداخلان لبناء الجملة. كما توجد فجوة في عرض النص المرجعي للاختبار، وتعارض بين عقد التكيّف الموثق وما تجمعه الخوارزمية فعليًا.

## المسار الفعلي للمحتوى

1. مصادر التأليف في `packages/content/src`، ومنها الكتالوج الأساسي والإضافات وسياسات الاعتماد.
2. `canonical_content_compiler.py` يدمج المصادر.
3. `canonical_release.py` يثبت الإصدار القانوني والبصمة.
4. `canonical_content_publisher.py` ينشر داخل معاملة إلى PostgreSQL.
5. خدمات API تقرأ عناصر المحتوى والخطوات والخيارات من PostgreSQL.
6. صفحات الطالب تعرض حمولة API ولا تبني محتوى أكاديميًا محليًا.

**الحكم:** موحّد في وقت التشغيل، لكنه ليس ملف تأليف واحدًا. طبقة التجميع هي نقطة التوحيد ويجب إبقاؤها المصدر التنفيذي الوحيد.

## ما ثبت أنه سليم

- الإصدار المجمّع: 125 عنصرًا و44 مهارة.
- التوزيع: 30 قبلي، 30 بعدي، 30 أساسي، 35 تقوية.
- Core: عشرة عناصر لكل مستوى. تقوية: L1=12، L2=11، L3=12.
- لا تكرار في canonical IDs أو stable keys.
- لا فجوات وسائط للمستوى الثالث في الإصدار المجمّع.
- لوحة المشرف تستبعد الأنشطة المستخدمة بالفعل من قائمة الاختيار.
- الناشر يعمل داخل معاملة ويختم بصمة الإصدار.
- CI للنسخة `0799ac1` أخضر: frontend/security/backend/integration.
